# Исправление логики модерации

## Проблема
После одобрения модератором данные пользователя (описание, фото, изменения профиля) не применялись к основному профилю. Данные оставались в `payload` таблицы `ModerationItem`, но не переносились в таблицы `Profile` и `Photo`.

## Решение
Добавлена логика применения одобренных данных к профилю пользователя в функции обработки модерации.

### Что исправлено:

1. **PROFILE_DESCRIPTION** - описание профиля теперь применяется к полю `description` и обновляется статус модерации
2. **PHOTOS** - фото получают статус `APPROVED` в таблице `Photo`
3. **INITIAL** - все начальные данные профиля применяются к соответствующим полям
4. **PROFILE_EDIT** - изменения профиля применяются к существующим данным

### Логирование
Добавлено подробное логирование для отслеживания процесса применения данных:
- Логи начала применения данных
- Логи успешного обновления каждого типа данных
- Логи ошибок с детальной информацией

### Безопасность
- Обработка ошибок с try-catch
- Проверка существования данных перед применением
- Отправка уведомлений об ошибках модератору

## Тестирование
После внесения изменений:
1. Перезапустите сервер
2. Проверьте логи при одобрении модерации
3. Убедитесь, что данные применяются к профилю пользователя
